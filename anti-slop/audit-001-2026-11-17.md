## Scope

This artifact records the anti-slop findings observed in the nearFind UI after the build. It covers the light and dark themes, document landmarks, motion behavior, typography rationale, interactive controls, and the final click-through. Each numbered finding cites the rule it violated, the evidence observed, the fix applied, and a one-line reason. Evidence comes from source inspection and browser checks performed in this session. No claim is made about rules that were not checked in this pass. The full Delivery Gate was run separately by the parent agent, one line per item, and is not reproduced here.

## Findings

1. Danger text failed contrast in the light theme (R-25, R-34)
   Evidence: `#FF9B9B` appeared 18 times as `text-[#FF9B9B]` and measured between 1.85:1 and 2.02:1 on the light theme, below the 4.5:1 minimum.
   Fix: Introduced `--color-danger` with dark value `#FF9B9B` and light value `#b42318`, then replaced all 18 classes with `text-danger`.
   Outcome: Canvas-aware audit reported 0 offenders in light and 0 in dark.
   Reason: The shipped light mode broke text contrast, which fails R-25 and R-34.

2. Missing document landmarks (R-39)
   Evidence: No `<main>` or `<footer>` landmarks were present in the document structure.
   Fix: Added `<main>` to the explore index, report, and profile pages, and `<footer>` to the app, auth, and welcome layouts.
   Outcome: Browser check reported main true and footer true on `/`, `/explore`, `/reports`, and `/profile`.
   Reason: A document lacking landmarks fails the accessibility checks in R-39.

3. Infinite skeleton loops (R-19)
   Evidence: The skeleton sweep used `infinite` animation iterations and the home need skeleton used `animate-pulse`, with no UX purpose recorded.
   Fix: Changed `infinite` to 2 iterations in `nf-skeleton-sweep` and removed `animate-pulse` from the home need skeleton. Motion still respects `prefers-reduced-motion`.
   Outcome: Skeletons now run a finite 2 iterations and honor reduced-motion preferences.
   Reason: Endless default motion without a stated purpose fails R-19.

4. Typography choices had no written reason (R-06, C-1, R-31)
   Evidence: The typeface and numeric styling were chosen without a one-line rationale in source.
   Fix: Added source comments explaining Instrument Sans as a civic and neutral voice, and the numeric tabular voice for figures.
   Outcome: Each typography decision now has its reason written down in the source.
   Reason: A typeface chosen without a written brand-character reason fails R-06, C-1, and R-31.

5. Point picker nudge buttons were inert (R-26, C-2)
   Evidence: `createPointPicker.bind()` passed camelCase selectors (`pointStep`) where the DOM uses kebab-case (`data-point-step`), so the buttons did nothing. Browser proof after the fix: north latitude -6.890300 became -6.888800, east longitude 107.594400 became 107.595900, and south and west returned to the start.
   Fix: Added an `attributeSelector` helper so the bindings match the kebab-case DOM attributes.
   Outcome: Each nudge button now moves the point by the expected step in its direction.
   Reason: Buttons that look active but change nothing are dead controls under R-26 and C-2.

6. Dark nav composite gave false low contrast (R-25, R-34)
   Evidence: The translucent nav sat over the default white html background, producing a misleading low-contrast reading in dark mode.
   Fix: Set `html { background: var(--color-canvas); }` so the page backdrop follows the active theme.
   Outcome: Canvas-aware audit reported htmlBg light rgb(247,245,241), dark rgb(11,14,18), and 0 offenders in both modes.
   Reason: Contrast must be tested over the real composite area, which failed R-25 and R-34 before the background was themed.

7. Need category label used an arbitrary text color (R-25)
   Evidence: A need category label was rendered with inline `style="color:${category.color}"`, so its text contrast was not guaranteed.
   Fix: Replaced the inline text color with `text-muted`. The icon label still uses the category color as a non-text accent.
   Outcome: Label text now uses the audited muted color, while the category color remains as a decorative accent only.
   Reason: Category color as text risked a failing contrast ratio under R-25.

8. Final click-through of the built app (R-35)
   Evidence: A recorded click-through was performed on the built app covering the card toggle, theme toggle twice, add-place sheet, filter sheet and category radio, login gate, nav links, keyboard Tab focus, search result selection, area selection, popup "Jadikan tempat", map marker and popup, and lazy map load per route.
   Fix: No further code change was required for these controls; the click-through supplied the evidence R-35 requires before delivery.
   Outcome: All listed controls behaved as expected. The only console entries were aborted tile-style requests caused by navigation.
   Reason: R-35 requires an element-by-element click-through recorded as evidence before a PASS can be claimed.

9. Empty state inverted and three camera moves stalled under frame throttling (R-27, R-26, C-2, R-35)
   Evidence: `renderPlaceResults` and `renderTopSearchResults` passed `status === 'ready' && count === 0` to `setChildHidden`, so the empty child was hidden exactly when the result count was zero and shown when results existed. After typing `semarang`, one area result was present while `[data-place-top-empty]` stayed visible with `Belum ada tempat yang cocok.`. Separately, the area-result click used `map.panTo(..., { duration: 350 })` and the picker's `nudge()` and `zoomBy()` used `map.easeTo(..., { duration: 160 })` and `{ duration: 180 }`. The calls reached MapLibre but the camera center did not advance when requestAnimationFrame was throttled, so `moveend` never committed the picker point.
   Fix: Both renderers now pass `status !== 'ready' || count !== 0`, so the empty child is hidden in every state except ready with zero results. The area-result click, picker nudge and picker zoom now use `duration: 0`, which takes MapLibre's synchronous ease path where `_ease` runs `frame(1)` and `finish()` directly. Short source comments record why the zero duration is intentional.
   Outcome: `node --check resources/js/app.js` passed with no output. A truth-table check confirmed the new empty predicate is the exact complement of the old one for every status and count pair. Source inspection confirms all three camera sites now use zero duration and the grouped result labels stay intact. A fresh browser click-through of these three paths was not run in this pass, so the visual result rests on the traced root cause and the MapLibre zero-duration path rather than a new browser observation.
   Reason: An inverted empty state fails R-27, and controls that visibly respond without changing the camera or the pinned point are dead controls under R-26 and C-2; R-35 requires the interaction to be checked before delivery.
   Residual R-35 surface: other animated camera sites were left unchanged because they are outside these three defects: `selectNeed` pan at line 2029 (350 ms), `selectLocation` pan at line 2610 (350 ms), `fitMapToFiltered` at line 2875 (350 ms), main-map `zoomBy` at line 2916 (200 ms), and geolocation `flyTo` at line 3019 (600 ms). The two `jumpTo` sites at lines 475 and 2898 are already deterministic. These five animated sites still need a browser click-through under R-35.

10. Stale coordinates when a later prefill reused an existing picker map (R-35, R-26)
   Evidence: In the final merged build, opening "Tambah Tempat" and selecting the Nominatim result "Semarang" set the hidden inputs to -6.990399 / 110.422910. Using the picker north, east, west and zoom controls and then "Pakai lokasiku" with emulated geolocation -6.9, 110.4 changed the hidden inputs to -6.9 / 110.4. After closing the sheet, the R-35 click sequence was: search "Semarang" on the main map, click the area result, then click the popup button "Simpan Semarang sebagai tempat". The sheet showed name and area Semarang, but the hidden lat/lng stayed at -6.9 / 110.4 instead of returning to -6.990399 / 110.422910. Root cause: `openLocationSheet` called `prefillLocationForm(prefill)` before removing the `hidden` class from `#location-sheet`, and `prefillLocationForm` only recentres when the sheet is not hidden. A later prefill therefore could not recentre an already-created picker map, because `locationPicker.ensure()` returns early once the map exists and leaves the stale centre captured on the first open.
   Fix: In `openLocationSheet`, reveal `#location-sheet` (remove `hidden`, add `flex`) before the `if (prefill) prefillLocationForm(prefill);` call. All other behavior is unchanged: `closeFilterSheet`, focus return, and the `requestAnimationFrame` ensure and focus remain in place. With the sheet already visible, `prefillLocationForm` now reaches `locationPicker.centerOn` for an existing map. First open still works through `ensure()` and `initialPoint()`, which read the prefilled hidden inputs when the map is created.
   Outcome: `node --check resources/js/app.js` exited 0 with no output and `git diff --check` was clean. Source inspection confirms the reveal now precedes the prefill call. A fresh browser click-through was not run in this pass, so the visual result rests on the traced root cause and the corrected ordering rather than a new browser observation.
   Reason: A prefill that leaves stale coordinates in the hidden inputs makes the save action use the wrong point, which fails the R-35 verification requirement and leaves the picker controls producing the wrong result under R-26.
   Parent re-verification: The parent agent must repeat the exact R-35 sequence in a browser on the final merged build: open "Tambah Tempat", select Nominatim "Semarang" (expect -6.990399 / 110.422910), use the picker nudge and zoom controls, use "Pakai lokasiku" with emulated geolocation -6.9, 110.4 (expect -6.9 / 110.4), close the sheet, search "Semarang" on the main map, click the area result, click "Simpan Semarang sebagai tempat", and confirm the hidden lat/lng return to -6.990399 / 110.422910 with the picker map recentred.
