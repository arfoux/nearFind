## Scope

This artifact records the anti-slop findings observed in the nearFind UI after the build. It covers the light and dark themes, document landmarks, motion behavior, typography rationale, interactive controls, and the final click-through. Each numbered finding cites the rule it violated, the evidence observed, the fix applied, and a one-line reason. Evidence comes from source inspection and browser checks performed in this session. No claim is made about rules that were not checked in this pass. The full Delivery Gate was run separately by the parent agent, one line per item, and is not reproduced here.

## Findings

1. Danger text failed contrast in the light theme (R-25, R-34)
   Evidence: `#FF9B9B` appeared 18 times as `text-[#FF9B9B]` and measured between 1.85:1 and 2.02:1 on the light theme, below the 4.5:1 minimum.
   Fix: Introduced `--color-danger` with dark value `#FF9B9B` and light value `#b42318`, then replaced all 18 classes with `text-danger`.
   Outcome: Canvas-aware audit reported 0 offenders in light and 0 in dark.
   Reason: The shipped light mode broke text contrast, which fails R-25 and R-34.

2. Missing document landmarks (R-39)
   Evidence: No `<main>` or `<footer>` landmarks were present in the document structure.
   Fix: Added `<main>` to the explore index, report, and profile pages, and `<footer>` to the app, auth, and welcome layouts.
   Outcome: Browser check reported main true and footer true on `/`, `/explore`, `/reports`, and `/profile`.
   Reason: A document lacking landmarks fails the accessibility checks in R-39.

3. Infinite skeleton loops (R-19)
   Evidence: The skeleton sweep used `infinite` animation iterations and the home need skeleton used `animate-pulse`, with no UX purpose recorded.
   Fix: Changed `infinite` to 2 iterations in `nf-skeleton-sweep` and removed `animate-pulse` from the home need skeleton. Motion still respects `prefers-reduced-motion`.
   Outcome: Skeletons now run a finite 2 iterations and honor reduced-motion preferences.
   Reason: Endless default motion without a stated purpose fails R-19.

4. Typography choices had no written reason (R-06, C-1, R-31)
   Evidence: The typeface and numeric styling were chosen without a one-line rationale in source.
   Fix: Added source comments explaining Instrument Sans as a civic and neutral voice, and the numeric tabular voice for figures.
   Outcome: Each typography decision now has its reason written down in the source.
   Reason: A typeface chosen without a written brand-character reason fails R-06, C-1, and R-31.

5. Point picker nudge buttons were inert (R-26, C-2)
   Evidence: `createPointPicker.bind()` passed camelCase selectors (`pointStep`) where the DOM uses kebab-case (`data-point-step`), so the buttons did nothing. Browser proof after the fix: north latitude -6.890300 became -6.888800, east longitude 107.594400 became 107.595900, and south and west returned to the start.
   Fix: Added an `attributeSelector` helper so the bindings match the kebab-case DOM attributes.
   Outcome: Each nudge button now moves the point by the expected step in its direction.
   Reason: Buttons that look active but change nothing are dead controls under R-26 and C-2.

6. Dark nav composite gave false low contrast (R-25, R-34)
   Evidence: The translucent nav sat over the default white html background, producing a misleading low-contrast reading in dark mode.
   Fix: Set `html { background: var(--color-canvas); }` so the page backdrop follows the active theme.
   Outcome: Canvas-aware audit reported htmlBg light rgb(247,245,241), dark rgb(11,14,18), and 0 offenders in both modes.
   Reason: Contrast must be tested over the real composite area, which failed R-25 and R-34 before the background was themed.

7. Need category label used an arbitrary text color (R-25)
   Evidence: A need category label was rendered with inline `style="color:${category.color}"`, so its text contrast was not guaranteed.
   Fix: Replaced the inline text color with `text-muted`. The icon label still uses the category color as a non-text accent.
   Outcome: Label text now uses the audited muted color, while the category color remains as a decorative accent only.
   Reason: Category color as text risked a failing contrast ratio under R-25.

8. Final click-through of the built app (R-35)
   Evidence: A recorded click-through was performed on the built app covering the card toggle, theme toggle twice, add-place sheet, filter sheet and category radio, login gate, nav links, keyboard Tab focus, search result selection, area selection, popup "Jadikan tempat", map marker and popup, and lazy map load per route.
   Fix: No further code change was required for these controls; the click-through supplied the evidence R-35 requires before delivery.
   Outcome: All listed controls behaved as expected. The only console entries were aborted tile-style requests caused by navigation.
   Reason: R-35 requires an element-by-element click-through recorded as evidence before a PASS can be claimed.
